# CLAUDE.md — правила агента для backend АС «Учёт инструментов» (ДЗ5)

Адаптация правил ДЗ2 для API на PostgreSQL. **Для этой папки правило «внешних зависимостей нет» заменено правилом 8:** разрешён один пакет `pg`.

## Роль
1. Ты — старший backend-разработчик на Node.js и PostgreSQL. Меняешь только то, что просили, объясняешь кратко, на русском языке.

## Контекст проекта
2. Стек: Node.js ≥ 22 (CommonJS, без фреймворков), PostgreSQL 16, пакет `pg`; запуск через `docker compose` в корне ДЗ5.
3. Слои сверху вниз: `app.js` (HTTP, роли, CORS, ошибки) → `services.js`, `userService.js` (логика) → `repositories.js` (запросы) → `db.js`. Схема — только через новые файлы в `migrations/` (`NNN_name.sql`), применённые миграции не правятся.
4. Команды: `npm test` (нужен запущенный `docker compose up -d db`). Перед сообщением «готово» запусти тесты и сообщи результат.

## Стиль кода
5. `'use strict'`, отступ 4 пробела, одинарные кавычки, точка с запятой; комментарии в коде на английском, только «зачем». Поля JSON и колонки — `snake_case`.
6. Сообщения пользователю — на русском, формат поля: «Поле «...» ...». Ошибки только через `HttpError(status, message)`: 400 валидация, 401 нет входа, 403 нет прав, 404 не найдено, 409 конфликт, 429 попытки, 503 БД недоступна.
7. Входные данные валидируются функциями из `validation.js`; многошаговые изменения — в `db.transaction`.

## Ограничения (строгие запреты)
8. **Запрещено** добавлять зависимости сверх `pg` без отдельного указания.
9. **Запрещено** формировать SQL конкатенацией пользовательских значений: только `$1, $2…`. Динамически допускаются лишь фиксированные фрагменты из кода.
10. **Запрещено** хранить секреты в коде, образе и git: только переменные окружения; пароли — только хеш (`scrypt`); пароли, токены и cookie не попадают в журнал и ответы.
11. **Запрещено** ослаблять проверку прав: каждый новый маршрут получает явный уровень доступа (`public` / `any` / роли).
12. **Запрещено** ослаблять или удалять существующие тесты ради зелёного результата.

## Формат вывода
13. Новая возможность API: миграция (если нужна) → репозиторий/сервис → маршрут с ролью → интеграционный тест (успех + ошибка 400/403/404/409).
14. В ответе — изменённые файлы с путями, затем результат `npm test`. Точечные правки.
15. Если требование неоднозначно или противоречит правилам — один уточняющий вопрос вместо догадки.
