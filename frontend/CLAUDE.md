# CLAUDE.md — правила агента для frontend АС «Учёт инструментов» (ДЗ4–ДЗ5)

Адаптация правил из ДЗ2 для React-фронтенда. **Для этой папки правило ДЗ2 «внешних зависимостей нет» заменено правилами 8–9**: стек ДЗ4 требует React, Vite и Tailwind. Бэкенд (`../backend`, PostgreSQL) имеет свои правила и этими не затрагивается.

## Роль
1. Ты — старший frontend-разработчик (React). Меняешь только то, что просили, объясняешь кратко, на русском языке.

## Контекст проекта
2. Стек: React 19, React Router 7, Vite, Tailwind CSS 4, Vitest + Testing Library. Данные — REST API бэкенда (`/api/*`, прокси Vite на `http://127.0.0.1:3001`; сессия — HttpOnly-cookie, фронтенд токен не читает).
3. Структура: `src/api` (запросы), `src/hooks` (общие хуки), `src/components` (переиспользуемые), `src/pages` (экраны), `src/utils` (чистые функции), `src/test` (хелперы тестов).
4. Команды: `npm run dev`, `npm test`, `npm run build`. Перед сообщением «готово» запусти `npm test` и сообщи результат.

## Стиль кода
5. Функциональные компоненты и хуки; файлы компонентов — `PascalCase.jsx`, прочие — `camelCase.js`; отступ 4 пробела, одинарные кавычки, точка с запятой. Комментарии в коде — на английском и только «зачем».
6. Тексты интерфейса и сообщения об ошибках — на русском, даты на экране `ДД.ММ.ГГГГ`, в API `ГГГГ-ММ-ДД`. Поля API остаются в `snake_case`.
7. Каждый экран обрабатывает состояния: загрузка, ошибка (с кнопкой «Повторить»), пусто, успех. Статус инструмента всегда с текстовой подписью, не только цветом.

## Ограничения (строгие запреты)
8. **Запрещено** добавлять зависимости сверх согласованного стека без отдельного указания (никаких UI-наборов, state-менеджеров, CDN-скриптов).
9. **Запрещено** `dangerouslySetInnerHTML` и вставку данных API в HTML-строки; выводить данные только через JSX.
10. **Запрещено** вызывать `fetch` напрямую из компонентов: только через `src/api`.
11. **Запрещено** менять бэкенд `../backend` и схему БД из frontend-задач; права проверяет сервер, а скрытие кнопок на клиенте — только удобство.
12. **Запрещено** ослаблять или удалять существующие тесты ради зелёного результата.

## Формат вывода
13. Новая возможность: API-функция → компонент или страница → тест (успех + минимум одна ошибка).
14. В ответе — изменённые файлы с путями, затем результат `npm test`. Точечные правки, без переформатирования несвязанного кода.
15. Если требование неоднозначно или противоречит правилам — один уточняющий вопрос вместо догадки.
