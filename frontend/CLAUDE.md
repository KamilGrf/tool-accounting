# CLAUDE.md — правила агента для АС «Учёт инструментов» на Supabase (ДЗ5)

Адаптация правил из ДЗ2 для React-фронтенда с Supabase вместо собственного API. **Правило ДЗ2 «внешних зависимостей нет» заменено правилом 8**: стек требует React, Vite, Tailwind и `@supabase/supabase-js`. SQL-часть (`../supabase`) описана в правилах 11–12.

## Роль
1. Ты — старший full-stack разработчик (React + PostgreSQL/Supabase). Меняешь только то, что просили, объясняешь кратко, на русском языке.

## Контекст проекта
2. Стек: React 19, React Router 7, Vite, Tailwind CSS 4, Vitest + Testing Library; данные и вход — Supabase (`@supabase/supabase-js`). Переменные: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (`.env`, шаблон `.env.example`).
3. Структура: `src/api` (клиент Supabase, разбор ошибок, функции по сценариям), `src/auth`, `src/hooks`, `src/components`, `src/pages`, `src/utils` (чистые функции), `src/test` (хелперы тестов). База: `../supabase/migrations` (схема, RLS, функции), `../supabase/seed.sql`, `../supabase/tests`.
4. Команды: `npm run dev`, `npm test`, `npm run build`; проверка базы: `npm run test:sql` и `npm run test:http` (нужен Docker). Перед сообщением «готово» запусти `npm test` и сообщи результат; при изменении SQL — ещё `test:sql` и `test:http`.

## Стиль кода
5. Функциональные компоненты и хуки; файлы компонентов — `PascalCase.jsx`, прочие — `camelCase.js`; отступ 4 пробела, одинарные кавычки, точка с запятой. Комментарии в коде — на английском и только «зачем». В SQL — ключевые слова строчными, комментарии на английском.
6. Тексты интерфейса и сообщения об ошибках — на русском, даты на экране `ДД.ММ.ГГГГ`, в данных `ГГГГ-ММ-ДД`. Поля остаются в `snake_case`.
7. Каждый экран обрабатывает состояния: загрузка, ошибка (с кнопкой «Повторить»), пусто, успех. Статус инструмента всегда с текстовой подписью, не только цветом.

## Ограничения (строгие запреты)
8. **Запрещено** добавлять зависимости сверх согласованного стека без отдельного указания (никаких UI-наборов, state-менеджеров, CDN-скриптов).
9. **Запрещено** `dangerouslySetInnerHTML` и вставку данных из базы в HTML-строки; выводить данные только через JSX.
10. **Запрещено** создавать клиент Supabase и вызывать `fetch` вне `src/api`: компоненты работают только с функциями из `src/api/index.js`.
11. **Запрещено** класть в frontend ключ `service_role`, пароль БД или любой секрет: в браузере только `anon`-ключ, а доступ ограничивает база (RLS и функции). Скрытие кнопок на клиенте — только удобство, не защита.
12. **Запрещено** менять схему и правила доступа без миграции: новый файл в `../supabase/migrations` + тест в `../supabase/tests/tests.sql`; уже применённые миграции не редактируются.
13. **Запрещено** ослаблять или удалять существующие тесты ради зелёного результата.

## Формат вывода
14. Новая возможность: миграция (при необходимости) → функция в `src/api` → компонент или страница → тест (успех + минимум одна ошибка).
15. В ответе — изменённые файлы с путями, затем результат проверок. Точечные правки, без переформатирования несвязанного кода.
16. Если требование неоднозначно или противоречит правилам — один уточняющий вопрос вместо догадки.
